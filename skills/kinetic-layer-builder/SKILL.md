# Kinetic Layer Builder

Build, edit, uplift, and debug Epicor Kinetic **App Studio layers** on a live system through the Cutova MCP tools (`MCPToolsKinetic-*`, detailed in `references/lens-mcp-tools.md`). A Kinetic app is a folder of `.jsonc` files; a **layer** is a JSON *diff document* that overlays them at load time, applied **server-side** — you author the diff, you never edit the base app. **Dashboards are the exception**: base dashboard apps (`Ice.UIDbd.*`) CAN be created and replaced wholesale via import — see `references/dashboards.md` (§D).

## ⛔ MANDATORY PRE-FLIGHT — complete this BEFORE authoring or editing ANYTHING

This skill has exactly one recurring failure mode: **authoring layer JSON from memory instead of from the references.** You (the model) do NOT have current knowledge of the Kinetic MetaFX format — your pretraining is wrong about it in specific, documented ways, and every "obvious" shape you can guess has a corresponding failure in `references/lessons-learned.md` that cost real users hours of import cycles. The references in `references/` ARE your knowledge of this framework. Treat the following as **blocking gates, not suggestions**:

1. **Classify the task**: entry-app layer work · classic FORM uplift · DASHBOARD work (`Ice.UIDbd.*`, DashboardID, tracker, gate, mass-update) · debugging. Dashboards → **Read `references/dashboards.md` IN FULL before anything else**; it is the self-contained authority.
2. **Read every Required Reading row that matches the task** (table below) — BEFORE writing any JSON. The rows are scoped to *sections*, so each read is 1–3 pages, not a whole file. Do not skip them because the task "looks simple"; the gotcha log is full of simple-looking tasks that took 20+ import cycles because a shape was guessed.
3. **Output a Reference Check before you build.** A short block, visible in your response: the task type, each reference § you read, and a one-line takeaway per §. If you are about to write a shape and cannot cite the § that governs it, you have NOT read enough — go back and read it. No Reference Check → no authoring.
4. **Never guess a property name, trigger shape, diff wrapper, or import format.** If it isn't in a reference you read this session, look it up first; if it isn't in any reference, say so and verify against the live system (`GetNativeKineticApp` on a delivered app) instead of inventing it.

## Mental model (read once)

An Epicor Kinetic **app** = `.jsonc` files: `layout` + `pages/*` (the component tree), `dataviews` (data sources — BO tablesets or BAQ results), `events` (logic on triggers), `rules` (declarative styling/enable/hide of bound controls), `tools` (toolbar), `strings` (captions), `patch` (app-level `%token%` constants). A **layer** is a manifest of named **sections**, each holding a `Diffs` array that overlays the matching base file. The manifest ships as a zip whose top folder is `Layers/`, path `Layers/<AppId>/<LayerName>.jsonc`; the layer record carries **two content blocks** — `Content` (published) and `SysCharacter03` (the App Studio draft, which a running App Studio renders and can re-freeze over your imports). When you write, keep both blocks identical (see `references/lens-mcp-tools.md`). Merging happens **server-side**; import **replaces the whole layer**.

Data lives in **dataviews**; the screen is a tree of **components** bound to `View.Column` via `epBinding`; **events** run actions on **triggers**; **rules** match components by binding and style/enable/hide them. That's the whole game.

## The round-trip workflow

Tool details (and their inconsistent parameter names) are in `references/lens-mcp-tools.md`. Order:

1. **Confirm the layer & publish state** — `MCPToolsKinetic-GetLayers` with `IncludeUnpublished:true`. **Check `HasDraftContent`**: if `true`, the user has unpublished App Studio work that exports won't show — have them publish first, or you'll drop it on re-import.
2. **Understand the classic customization** (if uplifting) — `MCPToolsKinetic-GetCustomizationByID`; inventory every bound control, rule, code-behind/BPM hook, grid, button. (Net-new: write the inventory from the user's description. Dashboards: `references/dashboards.md` §D.1.)
3. **Understand the base app** — `MCPToolsKinetic-GetNativeKineticApp`. This gives real base component ids, the exact system-event names to override/chain (`Update`, `Refresh`, `GetNew`, `AfterGetByID`), base rules to avoid conflicting with, and `patch` constants. Reuse base dataviews/events/combos; add only what's new.
4. **Download the CURRENT published layer** — `MCPToolsKinetic-GetIndividualLayer`; GET the off-band `downloadUrl` (never transcribe base64). **Re-read the published layer before editing**, since import replaces everything and a stale baseline silently drops prior commits. **Verify again after writing**: a success response means the call was accepted, not that the content is live. The manifest is in whichever of `Content`/`SysCharacter03` is non-empty.
5. **Modify the manifest.** **STOP — pre-flight gate: every shape you are about to write must be covered by a Required Reading § you read THIS session; if not, read it now.** First diff the record's `Content` vs `SysCharacter03` blocks — if they differ, the draft (`SysCharacter03`) holds user hand-edits to **adopt**, not overwrite. Then write **both blocks identical**. Follow the reference shapes exactly. For anything beyond a one-line change, **script the edit** (unzip -> patch the manifest JSON -> rezip) and keep the script for cheap iteration. Stamp every new event `"mode":"A","customizable":true,"disable":false`; every new rule `"customizable":true,"disabled":false`. Keep section versions right (layout/pages 3.0, events 5.0, rules 3.0, tools 2.0, dataviews 4.0, config 2.0). When adding a brand-new item to any `*.Diffs` array, copy a sibling's **full wrapper** `{"Id","Path","Value","Operation","Index"}` — a bare `{Operation,Value}` corrupts the whole section.
6. **Checkpoint** — `MCPToolsKinetic-Commit` (`InID`/`InLayerName`/`InComment`) for a rollback point.
7. **Import** — **FIRST, company scope (MANDATORY pre-ask, once per session):** before the session's first `MCPToolsKinetic-ImportLayer`, ask the user (`ask_user_choice`) whether the import targets the **Current Company**, **All Companies**, or **another specific company** — unless they already stated it in this session or in the request. Remember the answer and reuse it for every subsequent import in the session (re-ask only if the target layer/app changes in a way that makes the prior answer doubtful). Pass it via the function's `InCompany` input (a Company ID, or `All Companies`/`All`/blank = all companies — see lens-mcp-tools.md); if the connector's `MCPToolsKinetic-ImportLayer` tool doesn't expose `InCompany` yet, tell the user which scope will apply (omitted = All Companies) instead of silently defaulting. Then: `request_file_upload` -> `curl -T` PUT the zip -> `MCPToolsKinetic-ImportLayer` with the returned `fileRef`. Retry transient 400s (don't rebuild the zip). **If the import over an existing layer is REJECTED** (e.g. "customization already exists in another company", persisting across package shapes/companies), fall back to delete-then-reimport: confirm with the user, save the current server content locally, `MCPToolsKinetic-DeleteLayer`, then re-import under the SAME name (lens-mcp-tools.md).
8. **Test & loop** — ask the user to reload in App Studio with the console open and report results (have them **close App Studio / hard-refresh** first so the draft block doesn't mask your import). Diagnose with the error table in `references/uplift-and-debugging.md` (dashboards: `references/dashboards.md` §D.6), fix, and repeat from step 4.

## Quick-start cheat sheet (full detail in the references)

The highest-value, most-bitten facts. When any of these is in play, open the cited reference.

- **Render order = physical array position of the diff in the section's `Diffs` list, NOT the `Index` value.** To reposition, move the diff object; `Operation:"Move"` (`Value:null`) is real. (`layer-mechanics.md`, `lessons-learned.md` §3a/§10)
- **A new diff needs the full wrapper** `{"Id":"<id>","Path":"","Value":{...},"Operation":"Add","Index":<max+1>}`. Bare `{Operation,Value}` empties the whole section's list in App Studio. (`lessons-learned.md` §3p)
- **Events:** `"mode":"A"` (`"U"` = locked), disable key is **`disable`** (not `disabled`), `customizable:true`. **No `onChange` hook** — use `columnChanged`. (`events.md`)
- **The field search icon** (`enableSearch:true`) wires to `{"type":"EpBinding","hook":"onClick","target":"<DataView.Column>"}`. Base-searchable fields fire natively with no custom event; custom `_c` fields need the event. Bracket any write-back with `event-column-disable`/`event-column-enable` (top-level `dataTable`, not `param.dataTable`) to avoid loops. (`events.md`, `search-baq-rest.md`, `lessons-learned.md` §3y/§3w)
- **Tokens:** `{View.Column}` (curly, view fields), `%value%`/`%session.*%`/`%dataset.*%`/patch constants, `{{strings.Key}}`, `#_ raw JS _#` (double-evaluated — quote the whole thing if it returns a string). `%View.Column%` -> "Invalid session value". (`events.md`)
- **rest-erp:** `requestParamArgs` = round-trip send-`ds` (GetaNew/Update); `responseParamArgs` = fetch into views (GetByID — this is the Foreign Key View replication). Wrong one returns 200 but leaves fields blank. (`search-baq-rest.md`)
- **Dataviews:** EVERY hand-built view needs `id` + `table` + `tools` + `mode` — a missing `tools` block makes the view **disappear on import**; a missing `table` keeps it out of App Studio's Data View picker. BAQ views: + `schema:"baq"` + `data:"<BAQ>"`. BO views: + `serverTable`/`datasetId`/`serverDataset` (a REAL server tableset). Client views: + `datasetId`/`additionalColumns`. `sort` is `{column,descending}` (not columnName/sortDirection). (`rules-and-dataviews.md` §B12, `lessons-learned.md` §19)
- **Rules match by binding, not id** — a rule on a shared binding hits every control on it. Give custom controls a **unique `TransView.<Col>` binding** (columns are created on the fly) and rule that. `SettingStyle.Disabled|Invisible|ReadOnly` take ONE `epBinding`; `DisableColumns` takes `columns`; `DisableRow` takes `exceptTheseColumns` (real column names only). (`rules-and-dataviews.md`, `lessons-learned.md` §3c/§3d/§3n)
- **Read-only locking:** don't hand-roll a `DisableRow` rule on a dataview the base already governs — drive the base flag (`TransView.SysReadOnly`) and let the base rule lock/reverse. (`lessons-learned.md` §3l)
- **Live property behavior:** on buttons use `disabled` (not `enabled`) via `property-set`; shapes don't re-render `enabledCaption`/`enabled` live — use two pre-styled shapes toggled by `hidden`, placed adjacent. Prefer a rule + `TransView` binding over `property-set` when you can. (`components.md`, `lessons-learned.md` §3/§3m/§3n)
- **Keep ALL base layout sections** — pruning "empty" ones blanks the form. Reparent custom fields into base slots (`<panelId>#bodyComponents`, or a column's plain id) to mirror a classic layout. (`lessons-learned.md` §8/§3s/§3t)
- **Field grids = `metafx-matrix`** (it EXISTS on deployed builds): matrix node in a panel-card slot, `metafx-col` cells with component-level `x`/`y` + `model.width:"auto"`, exactly ONE control per cell, blank `ep-label` spacers for empty cells. **`model.columns` = ROW count (`max(y)+1`) and `model.rows` = COLUMN count (`max(x)+1`) — swapped, and cells beyond them silently CLIP.** Violations render partially with no error. Layers are authored FLAT: `parentId: "<id>#<slot>"` is the valid form. (`components.md` §3.3/§3.8a, `lessons-learned.md` §22)
- **Page nav:** a null `/navigation/epBinding` (or `dataSetId`) crashes the crumb bar with `Cannot read properties of null (reading 'split')` on load/Refresh — audit `/navigation/*` diffs first on any such crash. (`lessons-learned.md` §3aa, `layer-mechanics.md`)
- **Dashboard base-app `imports`:** copy shapes from a real generated dashboard or use `"imports": []` — the strings.jsonc item key is **`default`** (a guessed key crashes `GetApp`'s translation merge: preview passes, real menu launch 500s with a Correlation ID). Preview passing is never sufficient sign-off — test a real menu launch. (`uplift-and-debugging.md` §3, `lessons-learned.md` §23)
- **Import replaces everything & can lag** — re-download before each edit; when unsure, build the complete end-state. `GetIndividualLayer` returns only the **published** layer. (`lens-mcp-tools.md`, `lessons-learned.md` §3h/§3r/§3u)
- **Two content blocks:** `Content` = published, `SysCharacter03` = App Studio **draft** (an open App Studio renders it and re-freezes it over imports — "my change didn't take"). Write both identical; if they differ, adopt the draft's hand-edits first; have the user close App Studio before testing. (`lens-mcp-tools.md`, `lessons-learned.md` §18)
- **BAQ-provider grids:** `autoLoadColumns:true` and **no `columns` array** (a columns array emits a dynamic Select that throws "Invalid column name" on complex BAQs). `whereList` items are exactly `{column, condition, value}` — a boolean `honorNull` throws `t.replace is not a function` in layer-authored grids (yet generated dashboard apps emit `honorNull:false` and run — treat as tolerated there, omit when hand-authoring). `?{}` = required (blocks the query when empty — the **gate** pattern), `??{}` = optional; neither auto-quotes strings — quote string columns yourself. Column config is all-or-nothing: `autoLoadColumns:true` + no `columns`, OR `autoLoadColumns:false` + the COMPLETE list — and `serverPaging:true` forces the latter (hidden `columns` entries for key/`QuerySortBy` fields, or sorting breaks and result-view reads come back empty) — or skip the columns dance and force fields into the projection via `baqOptions.select: ["[Table_Field]"]`, unioned into the Select verbatim (`providerModel.columns` is never read by the Select path). VERIFIED (field-observed): newer client builds DROP **Updatable**-flagged UBAQ fields (and metadata-less columns) from the Select enumeration; `QuerySortBy` re-append masks it until a saved personal sort disables the band-aid — on any server-paged grid over a UBAQ, ALWAYS set `baqOptions.select` (full bracketed list; layer-JSON only, not in App Studio). (`search-baq-rest.md` §2.3–2.4b incl. §2.3c/§2.3d, `lessons-learned.md` §16/§20/§21)
- **Client filter dataviews:** `additionalColumns[].datatype` is a Kinetic token — `string`/`int`/`decimal`/`date`/`boolean`/`guid` — NEVER a SQL type like `"nvarchar"` (silently drops the view on import). A `DataTable` trigger's `target` is the **table** id, not the dataview id — the view id never fires. (`rules-and-dataviews.md` §B12, `events.md` §2.4)
- **Reusable combos** (e.g. `UserCodes.UserCodesCombo`): `type`/`subType` alone fetch nothing — emit the **full resolved model** (svc, svcPath, tableName, value/textField, filters + `filtersParams:["CodeTypeParam=<CodeType>"]`), or let App Studio resolve it once and adopt it. (`components.md` §6.2, `lessons-learned.md` §17)
- **Dashboards:** anything involving a classic DashboardID, `Ice.UIDbd.*`, tracker prompts, gates, updatable BAQ grids, mass-update, or creating base apps/layers by import → **`references/dashboards.md` IN FULL**, before building.
